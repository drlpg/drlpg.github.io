Nginx 反向代理实战：给 Next.js 应用做生产级部署

发表于2026-11-13|更新于2026-11-13|部署
|总字数:2.1k|阅读时长:7分钟|浏览量:
文章摘要

Next.js 应用在生产环境通常跑成一个 Node 进程（next start 或 standalone 的 node server.js），默认监听 3000 端口。直接把 3000 端口暴露到公网能跑，但有三个问题：没有 HTTPS、静态资源没有缓存策略、慢客户端和长耗时请求会直接拖住 Node 进程。

正确的做法是在前面放一层 Nginx 做反向代理：Nginx 对外只开 80/443，负责 TLS、压缩、缓存和超时控制；Node 进程只监听本机回环地址，专心渲染和跑接口。本文给出一份可直接套用的配置。

架构：请求是怎么走的

要点只有一个：公网只能访问到 Nginx，3000 端口不对公网开放。云服务器的安全组/防火墙只放行 80 和 443；如果是 Docker 部署，端口映射写成 -p 127.0.0.1:3000:3000，只绑定本机回环。

域名解析到服务器

第二步：写一份可直接用的反向代理配置

几个容易忽略的点：

  • 请求头必须透传。Host 不透传，Next.js 拿到的就是 127.0.0.1:3000；X-Forwarded-For 不透传，应用层看到的客户端 IP 永远是 Nginx 本机。日志、限流、风控都依赖这几个头，缺一不可。
  • **proxy_http_version 1.1**。默认是 1.0，1.0 不支持 keep-alive，每个请求都要重新建连；配了 1.1 才能复用上游连接。注意配了 1.1 后要显式处理 Connection 头（见下文 WebSocket 部分）。
  • /api/ 的超时要单独放宽。proxy_read_timeout 默认 60 秒，文档转换、图片处理这类接口超过 60 秒没返回数据，Nginx 就会掐断并返回 504。只在 /api/ 放宽到 600 秒，页面请求保持默认 60 秒，避免一个慢请求占住连接太久。
  • **静态资源缓存只给 /_next/static/**。页面 HTML 不能长缓存——它是不带哈希的动态内容，缓存了会导致用户看到旧页面。

第三步：测试配置并重载

养成习惯：每次改完配置先 nginx -t 再 reload，不要直接 systemctl restart nginx。nginx -t 失败时 reload 不会执行，线上服务不受影响；直接 restart 一旦配置有错，Nginx 起不来就是全站宕机。

常见问题排查

502 Bad Gateway

Nginx 能收到请求，但连不上上游。按顺序查：

  1. Next.js 进程还在吗：curl http://127.0.0.1:3000，不通就是应用挂了，先重启应用。
  2. 端口对得上吗：配置里的 proxy_pass 端口要和 PORT 一致。
  3. 看 Nginx 错误日志：sudo tail -f /var/log/nginx/error.log，connect() failed (111: Connection refused) 就是上游没在监听。

413 Request Entity Too Large

请求体超过了 client_max_body_size，默认值只有 1m，传个稍大的文件就触发。按文件大小在 server 块里调大（上文配了 50m）。改完记得 nginx -t && nginx -s reload；只改配置不重载是不生效的。

504 Gateway Time-out

上游超过 proxy_read_timeout 没返回数据。先确认接口本身是不是真的慢——是的话按上文把 /api/ 的超时放宽；如果接口平时很快、偶尔 504，优先查应用日志和数据库慢查询，不要无脑加超时。超时只是兜底，不是修慢接口的办法。

应用拿到的客户端 IP 不对

应用日志里全是 127.0.0.1，说明请求头没透传。检查 proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; 是否写了；应用层要读 X-Forwarded-For 的最后一项，那才是真实客户端 IP——链上每一跳都会把自己看到的来源 IP 追加到末尾，而前面的项客户端可以随意伪造；直接读连接来源 IP 读到的永远是 Nginx。

改了配置，线上没变化

三件套：nginx -t 是否通过、nginx -s reload 是否执行、浏览器是否走了缓存。先用 curl -I 绕过浏览器缓存验证，再怀疑配置。

小结

  • Node 进程只监听 127.0.0.1:3000，公网只开 80/443，所有流量经 Nginx 进出。
  • 一份 server 配置覆盖五件事：请求头透传、gzip 压缩、/_next/static/ 长缓存、/api/ 长超时、上传大小限制。
  • 改配置的固定流程是 nginx -t → nginx -s reload，不要直接 restart。
  • HTTPS 用 certbot --nginx 一键完成，证书 90 天有效、自动续期，跑完用 renew --dry-run 验证一次。
  • 502 查上游进程、413 调 client_max_body_size、504 先查接口本身再放宽超时——三个报错各有明确的排查路径，不用凭感觉调配置。
